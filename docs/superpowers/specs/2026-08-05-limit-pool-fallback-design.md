# 涨跌停池备用数据源接入设计

## 1. 目标

在不改变现有报告、因子和质量闸门口径的前提下，为
`LimitPoolProvider` 增加可审计的备用抓取链，降低 AkShare 包装层失效、字段漂移或
单一上游接口短暂不可用导致报告阻断的概率。

成功条件：

1. 主源健康时不调用备用源，保持当前行为和请求量。
2. 主源异常、返回 `None`、结构不合法或无可信数据时按固定顺序回退。
3. 每行记录实际数据来源，聚合状态记录每个池最终选择的来源和失败原因。
4. 涨停与跌停分别取数、分别判定；缺失任一核心池时结果不得伪装成成功。
5. 沪深北代码统一经过 `normalize_code()`，包括北交所 `920xxx`。
6. 所有新行为通过离线 fixture 测试，不依赖测试时访问公网。

## 2. 接入范围

涨停池按以下顺序尝试：

1. `akshare_em`：现有 `ak.stock_zt_pool_em()`。
2. `eastmoney_push2ex`：直连东财 `getTopicZTPool`，绕开 AkShare 包装层。
3. `ths_limit_up`：同花顺涨停揭秘接口，作为不同域名的独立末级备用。

跌停池按以下顺序尝试：

1. `akshare_em`：现有 `ak.stock_zt_pool_dtgc_em()`。
2. `eastmoney_push2ex`：直连东财 `getTopicDTPool`。

同花顺没有纳入跌停池备用，因为当前外部方案只提供可信的涨停揭秘端点。若跌停主源与
东财直连同时失败，聚合结果必须是 `partial` 或 `failed`，继续由现有质量闸门阻断发布。

本次不引入 `mootdx`，不替换 raw/qfq 价格链，不增加研报、资金流、龙虎榜、期权等与
当前核心报告无关的端点，也不把外部 `SKILL.md` 整体复制进项目。

## 3. 组件设计

### 3.1 HTTP 适配器

新增 `src/data_sources/limit_pool_sources.py`，只负责：

- 请求东财涨停/跌停池并返回标准化前的记录；
- 请求同花顺涨停池并返回标准化前的记录；
- 对 HTTP 状态、JSON 结构和业务状态做正向校验；
- 东财请求使用复用 Session、有限重试和最小间隔，减少风控概率；
- 网络异常和字段漂移向上抛出明确异常，不返回伪空列表。

端点契约参考 `simonlin1212/a-stock-data` V3.6.0 的 Apache-2.0 文档，但只实现当前项目
需要的最小字段，不复制无关端点。源文件保留简短出处说明。

### 3.2 Provider 回退编排

`LimitPoolProvider` 接受每个池的有序 fetcher 列表。为兼容现有调用，已有的
`fetch_zt`、`fetch_dt` 参数仍表示首选 fetcher；未显式传入链时组装默认链。

每个池独立执行：

1. 调用当前 fetcher。
2. 将响应标准化到 `LIMIT_POOL_COLUMNS`。
3. 非空且结构合法时立即选中，不再调用后续来源。
4. 结构合法的空容器记为一次“可信空候选”，继续尝试后续来源交叉确认。
5. 若后续来源返回非空，选中后续来源；若所有可调用来源均为可信空，池状态为 `zero`。
6. 若所有来源均异常或结构不合法，池状态为失败。

涨停和跌停均成功或可信为零时，聚合状态为 `success` 或 `zero`；只有一侧可用时为
`partial`；两侧都不可用时为 `failed`。

### 3.3 标准模型与来源记录

正式输出字段保持不变：

| 字段 | 说明 |
|---|---|
| `date` | `YYYY-MM-DD` |
| `pool_type` | `ZT` 或 `DT` |
| `code` | 标准内部代码 |
| `name` | 股票简称 |
| `limit_count` | 连板数；无值时涨停默认 1，跌停默认 1 |
| `source` | 实际选中的来源 |

`FetchResult.source` 使用可读的聚合形式，例如
`ZT:eastmoney_push2ex|DT:akshare_em`。`message` 记录被跳过来源的异常摘要，但不写入
密钥、完整响应或代理配置。

## 4. 错误与数据质量

- HTTP 200 但缺少预期数据节点视为结构失败，不视为零值。
- `None`、非 DataFrame/列表响应、缺少代码字段或代码无法标准化均视为当前来源失败。
- 同一响应中存在少量坏行时丢弃坏行并在消息中记录；全部为坏行时来源失败。
- 同花顺仅能补涨停池，不能让缺少跌停池的结果升级为成功。
- 现有 `MarketDataQualityGate` 对核心 `limit_pool` 的 `partial/failed` 阻断规则保持不变。
- Provider 不合并多个来源的股票集合，避免重复、时间差和口径差；始终选择第一个完整来源。

## 5. 测试设计

按照 TDD 顺序新增测试：

1. 主源返回合法非空数据时，备用 fetcher 不被调用。
2. 主源抛异常时，东财直连成功并写入正确来源。
3. 东财也失败时，涨停池可回退到同花顺，跌停池仍按自身链判定。
4. 主源可信空、备用源非空时使用备用源；所有来源可信空时返回 `zero`。
5. 涨停成功但跌停全失败时返回 `partial`，并保留涨停数据。
6. 主备源全部失败时返回 `failed`。
7. 东财和同花顺 fixture 解析为标准字段，`920117` 归一化为 `bj920117`。
8. HTTP 200 但 JSON 节点缺失时抛出结构异常。

完成后运行完整 `pytest`、`compileall` 和现有数据完整性审计。真实网络只用于可选的手工
smoke test，测试套件不依赖外部接口可用性。

## 6. 发布与观察

接入后先观察至少五个交易日的 `fetch_status.csv`：

- 主源命中率；
- 每个备用源启用次数；
- 主备结果数量差；
- `partial/failed` 次数；
- 北交所代码归一化异常数。

若备用源连续产生明显数量偏差，不自动扩大其优先级，先停用该来源并检查字段或市场范围。
本次改动不改变 GitHub Pages 发布触发方式。
