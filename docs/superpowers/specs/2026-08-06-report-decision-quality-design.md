# 报告决策质量改造设计

## 目标

把每日主线报告从“信息集合”改成可审计的次日决策简报：名称和行情口径统一，关键来源差异可见，市场状态只有一个，股票池角色互斥，场景标签来自历史样本而不是固定概率。

## 现状与问题

1. `industry_cache.csv` 同时承担行业和名称真源，摘帽、简称变化会污染 Top30 和核心中军池。
2. 涨停主源只要返回非空就被接受，无法识别非空但残缺的涨停池。
3. `timing_signal`、`market_stance` 和反弹复盘分别生成市场定性，页面可能同时出现“中性震荡”和“普涨反弹”。
4. `generate_focus_pool` 用 N 日涨幅直接生成中军池，空间龙头也可能被错误归类为趋势中军。
5. 决策看板的四个场景包含固定百分比，缺少样本数、口径和实际命中结果。
6. AI 接口失败时会使用规则文本，但页面没有明确显示降级状态。

## 设计

### 1. 名称真源与冲突审计

新增 `data_sources.name_resolver`，接受 universe、历史分类、当日涨停和行业缓存四类 DataFrame，输出：

- `code -> name` 的当前名称映射；
- `code -> source` 的名称来源；
- 同一代码存在多个非空名称时的冲突记录。

优先级固定为：当日涨停名称 > 最新 universe 名称 > 最近日期涨停分类名称 > 行业缓存名称。行业缓存只提供行业字段。所有 Top30、主线天梯、细分领涨和 focus pool 复用此映射；报告显示冲突数量，冲突不再静默覆盖。

### 2. 涨跌停来源一致性

保留现有回退链，并在主源返回非空后执行轻量东财交叉校验。校验比较涨跌停数量和二板以上代码集合：数量差超过 `max(3, round(primary_count * 0.05))`，或高板代码/高度不一致时，结果标记为 `partial`，记录差异摘要；不擅自把两个来源的股票集合拼接。质量闸门阻止带 `partial` 的发布。

### 3. 统一市场状态

新增 `market_regime` 计算函数，输入 A/D、涨跌停、连板梯队、历史情绪序列和来源质量，输出唯一的 `regime_code`、标题、颜色、操作语义和触发条件。`timing_signal` 和 `market_stance` 继续提供底层因子，但报告首屏只展示统一状态，反弹复盘引用同一个状态标题。

### 4. 股票池角色与历史样本

`generate_focus_pool` 强制角色互斥：

- `space`: 3 板以上或当前最高板，仅使用连板/封板证据；
- `trend`: 趋势中军，要求 N 日趋势、成交能力和非高位孤峰条件；
- `low_level`: 首板/二板补涨，要求题材同伴和晋级证据。

移除固定场景百分比。新增离线历史评估函数，以过去样本计算相似结构的样本数、T+1/T+3 结果和胜率；样本不足时显示“样本不足”，不生成概率。

### 5. 报告呈现

首屏顺序固定为：日期/数据质量 → 唯一市场状态 → 关键数字 → 明日观察池 → 场景触发条件。详细图表、板块矩阵、Top30 和催化证据放入可折叠的研究层。AI 卡片显示 `AI` 或 `规则降级`、生成时间和错误摘要。

## 失败处理

- 名称冲突不阻止报告，但必须记录并以高优先级名称渲染。
- 涨跌停交叉差异、核心池缺失、来源状态为 `partial/failed` 时阻止发布。
- AI 不可用不阻止报告，但必须显示规则降级标识。
- 历史样本不足不阻止报告，只隐藏概率并显示样本数量。

## 验证

- 名称解析、冲突和摘帽案例离线测试；
- 涨停数量差异、高板集合差异和正常一致案例离线测试；
- 市场状态互斥和降级标签测试；
- 股票池角色互斥、ST 过滤和样本不足测试；
- 报告 HTML 关键标签和 source/quality 元数据测试；
- 完整 pytest、compileall、数据完整性审计，并生成一次本地报告检查结果。
