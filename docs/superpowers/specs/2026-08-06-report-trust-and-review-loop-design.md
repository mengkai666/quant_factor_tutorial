# 日报可信发布与复盘闭环设计

## 1. 目标

在沪深北全 A 股数据链路修复基础上，把日报从“指标汇总页”升级为可审计、可降级、可回测的复盘决策产品。最终系统必须同时满足：

1. 事实、观察、决策三层隔离，数据不完整时不泄漏仓位、买卖、概率等交易语义。
2. 每个报告模块拥有独立质量状态，局部缺数不应掩盖仍可信的事实，也不能放大为全局结论。
3. 连板复盘按逐股链路计算昨日梯队到今日的晋级、断板和负反馈，而不是仅比较聚合数量。
4. 首屏明确展示“相比上一交易日发生了什么”，所有变化都可追溯到结构化快照。
5. 历史概率必须带样本量、置信区间、基准概率和校准指标；样本不足时不发布百分比。
6. AI 只能消费通过质量校验的结构化事实，并受发布模式约束；失败和回退必须显式记录。
7. 每个关键指标保存数据来源、时间、覆盖、降级原因和校验结果。
8. 每日预测在 T+1/T+3 自动回填实际结果，形成可验证的复盘闭环。
9. 主报告、独立看板、首页摘要和邮件使用同一份报告上下文，不得各自重新判断。

## 2. 总体架构

日报流水线固定为：

```text
Provider 原始数据
  -> 标准化数据模型
  -> 数据质量与血缘
  -> 派生事实指标
  -> 观察与历史证据
  -> 发布策略
  -> AI 受控摘要
  -> 单一 ReportContext
  -> 主报告 / 独立看板 / 首页 / 邮件
  -> 预测快照与后验复盘
```

渲染层不得直接读取外部数据、重新计算业务指标或推断发布模式。

## 3. 统一发布策略

发布模式保持三态：

- `facts_only`：只允许事实、来源、覆盖、缺口和中性描述。
- `observation`：允许方向性观察和条件触发，不允许确定仓位、买卖动作和情景概率。
- `decision`：数据与历史证据充分时，允许概率、仓位和操作条件。

统一 `ReportPolicy` 管理能力，而不是靠模板字符串分散判断：

```text
allow_facts
allow_observations
allow_scenarios
allow_probabilities
allow_positions
allow_actions
allow_ai
```

在非 `decision` 模式，对全部输出执行交易语义扫描。发现禁用词时视为测试失败；生产运行中降级为中性文案并记录质量告警。

## 4. 分模块数据质量

质量上下文包含以下模块：

- `universe`
- `price_raw`
- `price_qfq`
- `breadth`
- `limit_pool`
- `echelon`
- `sector`
- `history`
- `ai`

每个模块记录：`status`、`coverage_pct`、`source`、`source_timestamp`、`missing_fields`、`errors`、`lineage`。全局发布模式由需要形成决策的关键模块聚合而来；单个页面区域使用自己的模块质量决定是否展示。

## 5. 股票身份和可交易范围

内部股票键统一为 `sh/sz/bj + 六位代码`。证券主数据按有效日期保存名称、ST 状态、上市/退市状态和交易状态。报告同时展示两种口径：

- `沪深北全 A`：市场事实统计口径。
- `短线可交易池`：显式排除停牌、退市整理、新股异常阶段、ST 等规则后的策略口径。

任何过滤必须展示过滤规则与数量，禁止用策略池结果冒充全市场事实。

## 6. 连板晋级链路

为每个前一交易日连板股票匹配当日状态：

```text
promoted / broken_positive / broken_negative / limit_down / suspended / missing
```

输出每一高度的样本数、晋级数、断板数、负反馈数和 Wilson 区间。缺少昨日逐股样本时显示“样本不足”，不得从今日聚合梯队反推晋级率。

## 7. 昨日变化摘要

新增 `DailyDeltaSnapshot`，至少包含：空间高度、涨跌停家数、市场宽度、梯队完整度、板块集中度、晋级率和主线排名。每项记录今日值、昨日值、变化、可用状态和原因。

首屏只选择最重要的 3～5 个变化，并按“事实 → 观察 → 条件”表达。

## 8. 历史情景校准

历史情景输出：样本数、命中率、Wilson 置信区间、基准概率、相似度、最近样本日期、Brier Score。小于最低样本阈值时不显示概率。所有预测保存到不可变快照，后续按 T+1/T+3 回填结果并计算校准指标。

## 9. AI 受控输出

AI 输入是版本化 JSON，不传递未经校验的自由文本。输出固定为：`facts`、`observations`、`conditions`、`risks`、`decision`。发布策略在调用前和返回后各校验一次：

- `facts_only`：跳过 AI。
- `observation`：`decision` 必须为空，并过滤动作、仓位和概率。
- `decision`：允许输出，但必须引用输入事实键。

AI 成功、失败、超时、规则回退、模型和数据指纹进入血缘记录。

## 10. 数据血缘与闭环存储

关键指标写入 `output/audit/<date>.json`；预测写入 `data/report_prediction_history.jsonl`。写入必须原子化。历史结果回填时不修改原始预测字段，只追加 outcome 与评分。

## 11. UI 一致性

主报告、看板和首页共用 `ReportContext`。首屏固定展示：

1. 发布状态与可用范围；
2. 数据质量；
3. 今日核心事实；
4. 相比昨日变化；
5. 条件观察或决策；
6. 后验复盘状态。

数据阻断时不显示情绪温度计的方向标签、情景卡、仓位卡和股票买卖字段。

## 12. 验收标准

1. 沪深北 universe 含 `bj/sh/sz`，覆盖率来自真实有效记录并可对账。
2. 价格缓存不混用不复权和前复权列，异常迁移不覆盖旧文件。
3. `facts_only` 与 `observation` 的所有页面通过禁用语义扫描。
4. 分模块质量在局部缺失测试中按预期降级。
5. 连板晋级链路用逐股样本计算并有样本不足测试。
6. 昨日变化快照在缺值、零值和正常值下区分正确。
7. 历史概率、AI 门禁、血缘和 T+1/T+3 闭环均有单元与集成测试。
8. 主报告与独立看板使用相同发布模式和核心指标。
9. 完整 `pytest`、`compileall`、数据审计和真实日报运行通过。
