# 逐策略资格与条件预案设计（用户已确认）

目标：解除“所有增强模块必须同时完整”的全局捆绑，同时保留核心行情、具体策略依赖、独立验证和目标时点确认。不得为了产生买入名单而伪造样本或默认启用策略。

## 统计契约
- 统一 strategy-validation/v1：策略ID、规则版本/指纹、结果定义、样本窗口/唯一ID、样本数、验证方法、来源、评估时间、有效期。仅同策略同规则且已完成的独立验证才可授权。
- win_rate_sample_size 为历史描述统计，不因字段改名变成验证通过；单独保存描述样本和授权样本。market-thesis结果率不等于交易策略验证。
- 未提供、过期、混策略/混版本、未知/未成熟样本保持 unverified；有效审批记录需 source、evidence_ref、样本ID、样本日期、out_of_sample、passed；最低样本数不低于原10。
- 可选 data/strategy_validation.json 是显式验证输入，默认不存在即未验证；提供只读检查命令，展示期望指纹和失败原因，不能通过命令自动批准。

## 事件资格
- 每个指标独立区分 ready / missing / invalid / not_applicable。零事件只在完整观测证明为零时允许 not_applicable，不伪装缺失为0。
- 字段覆盖和样本范围分别判断；收盘涨停池不能替代全市场尝试样本。依赖全市场指标的策略要求明确全样本范围。
- 主线延续可将“完整观测但无炸板”的历史回封率记为不适用；分歧回封策略无适用事件时不启用；核心抱团依赖自身板型而非全市场回封率。

## 逐策略资格
- 注册现有场景策略及明确依赖，不新增“容易通过”的替代策略。未知策略拒绝。AI仅为增强文案，不作为这些确定性规则的依赖；仍须策略独立验证。
- 四核心模块 universe / price_raw / breadth / limit_pool 必须全部通过、非过期且批次一致；其他模块按具体策略依赖检查。
- 资格独立于发布健康：整体数据可degraded但某个被独立验证的策略可获条件许可。候选、零仓位和失效门禁保持。
- 盘后未确认时显示“条件预案，等待确认”；盘中只确认当前被授权策略，同日期/时区/阶段/预测修订绑定。不从其他策略借用支持。
- 报表、CSV、审计、每日记录、phase重放使用同一资格对象；可见逐策略未启用原因和恢复条件。

## 边界
- 不改代理/API Key/模型；不新增定时任务、不抓全量行情、不下单、不伪造真实收益。
- Python >=3.10；PowerShell7/UTF8；使用本地codex分支，最终按既有同步要求正常合并master，不强推。
- 已有历史缺乏独立策略验证，修复后仍可能观察；这是如实未验证，不是新逻辑永远无法满足。用正/负回归证明有证据时通路可达。
