## 二、实证发现的问题（按严重度排序）

### 🔴 P0 — 价格缓存复权口径混用（最严重）

**现状**: `price_history_cache.csv` 同时混有 baostock **前复权**价和腾讯**不复权**快照, 且二者交替落库。

**实证证据**:
- 全库 937,839 行中, **53,910 行 close 非 2 位小数** (前复权计算价特征), 涉及 84 个交易日, 集中在 2026-03 ~ 2026-06 (2026-04-30 单日 2,084 行)
- **1,420 条单日 |涨跌|>25% 的伪异常** (A 股实际不可能), 涉及 57 个交易日、409 只股票; 其中 628 条同时命中"精度异常", 坐实为复权口径跳变而非真实行情
- 典型案例: `sz300062` 2026-07-23 单日 +43.1%、`sh603709` +28.2% (2 位小数→9.52103488 前复权价跳变)
- 缓存里还有极值失真: 涨停缓存 18 连板、单日 -32% 等

**危害**: A/D 家数比、N 日涨幅、板块收益、回测全部被污染; 这正是 findings.md 记载的 1,419 条异常问题, **至今未修复**。

**根因**: `update_price_cache()` 的腾讯 fastpath 写不复权价, baostock 兜底写前复权价, 两条路径共用同一张表, 无口径标记、无原子重建。

### 🔴 P0 — 北交所股票完全缺位

**现状**:
- universe (industry_cache) 只有 **5,190 只沪深代码, 0 只北交所**
- 价格缓存同样无 `bj` 前缀代码
- 涨停缓存却有 **113 条北交所记录** (920726.BJ / 920407.BJ 格式), 且代码格式混乱: `sh/sz` 前缀、裸 6 位码 (`600855`)、`920xxx.BJ` 三种并存, 标准化后仍有 179 行无法对齐价格缓存

**危害**: 北交所涨停股无法参与 A/D 统计、收益计算、板块归因; task_plan.md 已决策"universe 含沪深北全 A", **尚未实施**。

### 🟠 P1 — sentiment 缓存早期零值污染

- 2025-09-19 ~ 2025-11-03 共 **26 行 up+down=0** (占全部 211 行的 12%), 其中 2025-10-23 ~ 11-03 连续 8 天全零
- 零值日期会被 `score_ema` 平滑拉低, 污染情绪历史曲线; 体检工具 `MIN_MARKET_BREADTH` 只覆盖价格缓存区间, 早期段无人审计

### 🟠 P1 — LongHu API 不可作历史真源

- 已确认对不同历史日期返回相同最新快照 (findings.md), 主程序靠"逐日 key 比对"打补丁, 但 `limit_ratio_factor.py` 里的 `_fetch_longhu_sentiment` **没有这套陈旧检测**, 存在二次污染风险
- 龙虎榜接口无 SLA, 属非公开接口, 随时可能变更

### 🟠 P1 — baostock 稳定性与能力天花板

- **实测登录挂起 2 分钟+ 无响应** (本机), 主程序已被迫为它写 5 秒超时 + 多进程探测 + 串号护栏
- 只覆盖沪深, 无法支撑"沪深北全 A"目标
- 逐股抓取全市场 5,000+ 只需 2~3 分钟 (多进程), 相比腾讯批量快照 (2 秒) 慢两个数量级

### 🟡 P2 — 东财接口被代理墙 / 不稳定

- 实测 `push2.eastmoney.com` 走系统代理 → ProxyError; 绕代理直连 → RemoteDisconnected (时通时断, 与 em_board.py 注释一致)
- 全市场概念归因 (em_stock_plates.py) 依赖该接口, 失败时静默降级, 归因率从 94% 掉回行业回退
- 同花顺热门股 API 同样不稳定

### 🟡 P2 — 工程层问题

| 问题 | 说明 |
|---|---|
| `industry_cache.csv` 无自动生成逻辑 | CI 缓存丢失后无法冷启动 (findings.md), 且无日期戳, 无法判断新鲜度 |
| CI 体检不阻断发布 | `continue-on-error: true`, 且位于报告生成之后, 坏报告仍会被部署 |
| `gap_dates.txt` 已过时 | 3~5 月缺口其实已补, 但 2026-05-14~28 覆盖仅 4,741/5,190 (91%) 未列入 |
| AI 研判 503 频发 | 中转 API 三次重试全 503, 报告降级为规则模板 |

## 三、更优数据源推荐

### 核心建议: 用腾讯系接口统一行情层, 淘汰 baostock

实测腾讯系接口**全部秒回且零鉴权**:

| 候选源 | 能力 | 实测 | 替代对象 |
|---|---|---|---|
| `qt.gtimg.cn/q=` 批量快照 | 全市场实时价 + 涨跌幅, 800只/请求, 5000只≈2秒 | ✅ 0.1s | 保留为 A/D + 最新日真源 |
| `ifzq.gtimg.cn/appstock/app/fqkline/get` | 日/周/月 + 5/15/30/60 分钟 K 线, **qfq/hfq/不复权三口径** | ✅ 0.1s | **替代 baostock 历史 K 线** |
| `ifzq.gtimg.cn` 分钟K | m1/m5/m15/m30/m60 | ✅ 0.2s | 盘中增强 |
| 腾讯快照/分钟K | **支持北交所 `bj920726` 格式** | ✅ 已验证 | 补齐北交所空缺 |

**优势**: 同源同口径 (腾讯不复权快照做 A/D, 腾讯 qfq 做收益/回测), 根除"前复权/不复权混列"; 支持北交所; 无 socket 挂起问题; 速度提升 60 倍以上。

### 各层推荐组合

```
行情层 (统一腾讯, 不再混源)
├── 全市场价格快照   qt.gtimg.cn        (A/D 真源, 不复权)
├── 历史日K(前复权)  ifzq fqkline qfq   (收益/排行/回测)
├── 历史日K(不复权)  ifzq fqkline       (A/D 历史, 可选)
└── 北交所行情       同接口 bj 前缀       (补齐 universe)

涨停/连板层
├── 涨停主源          CLS (保留, 题材归因独有优势)
├── 涨停回退+跌停     东财 push2ex (akshare 已封装, 保留)
└── 涨停原因/题材     CLS up_tags / 东财涨停揭秘

板块归因层
├── 东财 slist (em_stock_plates 保留, 绕代理重试已内置)
└── 失败兜底         行业映射 (industry_cache 回退)

universe 层 (建议改东财 clist, 替代 baostock 行业)
├── 全A列表(含北交所) push2.eastmoney.com/api/qt/clist/get
│                     fs=m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23,m:0+t:81+s:2048
├── 行业分类         东财 f100 行业 / 申万行业
└── 自动刷新         每日 16:30 跑批前刷新, 带日期戳

交易日历层
└── akshare tool_trade_date_hist_sina (保留, 稳定)
```

### 不建议引入的重型方案（成本/收益不匹配）

| 方案 | 不推荐原因 |
|---|---|
| Wind / 同花顺 iFinD / Choice 商业终端 | 付费、SDK 授权、CI 不可用 |
| Tushare Pro | 需积分/付费提额, 单日 500 次限制, 全市场逐股拉 5000 只会被限 |
| akshare 全量替代 | 依赖东财/新浪等无 UA 会被断连的接口, 且已实测东财不稳定 |
| 本地通达信/mootdx | 需维护行情服务器, 与 GitHub Actions CI 架构不匹配 |

## 四、分阶段落地建议

1. **立即 (P0 止血)**: 统一价格缓存口径 —— 新增 `adjust` 列或拆分表, 重建价格缓存, 只保留腾讯不复权 (A/D) + 腾讯 qfq (收益) 两套序列, 禁止混列
2. **本周**: universe 换成东财 clist 自动刷新 (含北交所), 标准化代码格式 `sh/sz/bj + 6位`
3. **本周**: `limit_ratio_factor.py` 补陈旧检测 (与主程序同判据), 清零早期 sentiment 零值段
4. **2周内**: `industry_cache` 生成逻辑入仓, CI 冷启动可复现
5. **2周内**: CI 体检改阻断闸门 (置于发布前, 去掉 continue-on-error)
6. **远期**: 主入口拆分 (task_plan 阶段7), Provider 抽象, 腾讯 ifzq 替代 baostock
