# 今日复盘 → 明日推演：如何读、怎样验证

## 先看结论，不从“0成”猜系统是否正常

首屏显示同一份计算结果的四个维度：核心行情资格（通过/缺失/过期）、策略资格（适用/不适用/尚未验证）、信号（未触发/已满足/已失效/不可评估）、操作结论（不开新仓/等待确认/进入可执行计划）。AI文案失败不会被混同为全部行情缺失，但不会因此豁免原有发布门禁。

“模型参考区间”是原有仓位规则的计算值，不是当前授权。未获得计划许可时，页面显示“当前未授权”；CSV 的“建议仓位”为“不新增仓位”，原值单列“模型参考仓位”。计划、信号、成交是三个不同概念。

## 明天究竟观察谁

- 同一份 `candidate_funnel` 供情景、首屏、CSV 和审计使用；先精确匹配主线，再按既有二板/三至五板角色、板高和代码稳定排序。排名不是收益预测。
- 最多1只首选、2只备选，并受有效情景的候选范围限制。其他题材、排序外对象与风险锚不能被CSV标为可执行。
- 未获许可仍可显示少量同主线**观察对象**，不把它们命名为买入清单；其余对象和未采用原因折叠。风险锚不等于持仓，未提供持仓时不生成实际加减仓指令。

## 情景排名不等于有效情景

- 最高排名只是先验与累计证据排序；有效情景是尚未失效的可评估分支；可决策情景要求必要规则全满足，且仍受数据、策略、仓位和候选门禁约束。
- 硬失效不能被其他正分抵消；同计划失效后不能靠后来变好的一条快照自动复活，需重新生成并验证计划。
- 必需字段缺失为不可评估；必需条件为假则未确认；可选字段缺失保留记录，不冒充0。
- 收盘仅是下一交易日的基准，不用于“自我确认”次日预测。已明确缺失的情景发生先验，不用历史条件命中率顶替；没有合格先验就不发布后验百分比。

## 盘中阶段：显式导入，不自动抓数或调度

目标交易日只从已有交易日历缓存读取；缺日历时保持未知，不用工作日猜节假日。观察时刻按上海时间验证：

| 阶段 | 允许时刻 |
|---|---|
| 竞价 | 09:25:00–09:29:59 |
| 9:35 | 09:35:00–09:44:59 |
| 10:00 | 10:00:00–10:15:00 |
| 午后 | 13:00:00–14:59:59 |
| 收盘基准 | 报告日15:00后，不能是次日收盘 |

时间必须带时区、观察日与 `trade_date` 一致且为预测目标日。缺来源、质量未通过、过期或错日数据不得确认。已有ID不能绕过校验；较新坏数据不能偷偷回退较早绿灯。只填写实际获得的指标，缺失填 `null`；不能复制收盘值充当竞价，也不能把导入成功当作 `quality=ok`。

以下是命令格式，日期、时刻、来源与文件均须替换为真实观察值：

```powershell
python tools/record_market_phase.py --report-date YYYY-MM-DD --trade-date YYYY-MM-DD --phase early_0935 --captured-at "YYYY-MM-DDT09:35:00+08:00" --source "实际行情来源" --quality-status ok --metrics-json "真实指标.json"
```

- 命令不联网、不创建定时任务、不调用AI、不下单。可用 `--source-as-of` 保留来源截止时刻，不能用新抓取时间洗白旧行情。
- 读取原预测的门禁、候选和规则，追加阶段快照、每日决策修订与原计划状态变化。旧预测缺少决策上下文时仅更新证据，不生成执行许可。
- **没有全自动盘中数据接入，也没有自动成交/持仓回填**。未导入阶段保持待确认。

## 数据源字段保留与观测

正常抓数在旧表裁剪前保存事件至 `data/limit_events/YYYY-MM-DD.json`：首次/最后封板、炸板次数、封单资金、换手率、成交金额、流通市值，以及源实际提供的尝试/炸板/回封/板型标记。

- 只保留真实源字段与原始证据；不从收盘仍涨停推断从未炸板、回封、一字板或换手板。`0/False` 与未提供分别保留。
- 源日期（包括东财 `qdate`）标准化核验，原值存 `trade_date_evidence`；抓取时间不当作事件发生时间。
- 覆盖率分母仅为输入收盘样本，不是全市场封板尝试集合。**全市场炸板率保持为空**；新字段只作观测，不绕过现有炸板/回封门禁。
- 历史缓存没有字段时明确未提供，不为补齐报表批量重抓旧行情。

## 每天都有决策记录，结果可以迟到

`data/report_prediction_history.jsonl` 新增 `daily_decision`，包括不交易日。六类为行情不足、策略未验证、市场防守、无候选、等待确认、条件计划。记录原因、恢复条件、目标日、有效情景和候选指纹。

相同最新内容幂等；变化追加修订，保留 A→B→A。首选变备选或计划失效仍是同一逻辑计划，不膨胀计划数。报表显示相比上一条记录的变化，并包含历史计划而不只当天。

实际结果通过 `trade_plan_review.append_trade_plan_outcome_once` 显式录入；多修订时明确 `plan_revision_id`，避免迟到结果错绑。`unknown` 可后续补确认，信号不能推导成交。净收益需明确成交、有限数值、来源、币种和口径齐全；不同币种/口径不混算。多修订的成交若无法辨别是否重复，不猜测合并收益。

历史筛选按计划报告日并纳入迟到确认，不宣称为当时已知的 point-in-time 截面。

## 离线验收

```powershell
python tools/preview_recap_report.py --audit output/audit/YYYY-MM-DD.json --history data/report_prediction_history.jsonl
python -m pytest -q -p no:cacheprovider
python -m compileall -q src tools
```

预览写入 `output/recap_validation/`：紧凑首屏、完整看板、内嵌版本、CSV、语义对照JSON及独立模拟日志。原审计、正式行情与交易日志不变；新增预览记录标为离线重算，不冒充当日真实决策。

这次不改AI密钥/模型/代理，不新增自动任务，不放开原门禁。缺失的实时数据、统计验证与真实成交仍须通过明确流程补齐。

现有CI仅增加事件目录缓存，不新增定时任务或网络请求。新预测按事实、规则、候选指纹和目标日标识修订，盘中输入绑定对应预测；旧修订证据不用于确认新规则。

## 逐策略门禁升级

整体数据健康与具体策略许可已分离；AI失败不再否定已独立验证的规则策略。新说明见[逐策略资格](strategy-qualification.md)。核心行情门禁、样本范围、验证证据与阶段确认仍必须通过。
