# 抱团周期：补充理解与优化建议

- 分析日期：2026-10-21（Asia/Shanghai）。
- 对象：项目的历史叙事版 `baotuan_cycle` 与证据核验版 `crowding_cycle`。
- 核验基准：当前工作区源码、本地 2026-10-20 研究 JSON，以及离线机制复现。
- 本文是设计建议，不是已上线功能、当前市场定性或经回测验证的交易策略；没有核验所涉个股的外部真实行情。
- 本轮只新增本文，没有修改引擎、数据缓存、历史报告或发布入口。

> 以上为 2026-10-21 的分析基线；2026-10-24 续接实现及验证记录见第十一节。原始复现与测试结果保留，不代表当前代码仍有同样问题。

## 一、结论：从“龙头故事”升级为“群体状态 + 失效条件 + 执行约束”

项目值得保留的思想是：龙一断板不等于群体周期结束；新方向需要跨日验证；允许等待；复盘要观察失败样本，而非只记住最后赢家。

我的补充定义：**抱团研究关注的不是某只股票涨得多，而是一个事前可识别的群体，其相对强势、交易关注与风险是否持续集中，以及这些特征何时失效。**

没有持仓与投资者交易数据时，应称“价格/成交抱团代理”，而不是直接认定机构抱团。持仓集中、成交集中、价格同步是不同变量；题材标签相同也不是资金迁移的证据。

这里建议先区分三种研究假设，分别验证，不要统一使用一套龙头战法：

| 假设类型 | 需要观察的现象 | 需要防止的误判 |
| --- | --- | --- |
| 扩散型主线 | 核心相对强、同伴广度和持续性改善 | 把一只强股误当全板块共振 |
| 收缩型抱团 | 全市场偏弱，活跃/成交集中于少数标的 | 把集中度升高误当环境改善 |
| 独立强势个股 | 个股持续强，但群体关联证据不足 | 为它事后拼接一条“龙头接替链” |

这些是待验证分类，不是已证实的市场定律。

### P0-1：历史叙事与实时判断使用不同权威级别

旧版 `build_baotuan_cycle` 的 396—424 行：请求日期只要大于等于 2026-10-08，就进入同一组阶段、战术与标的描述。市场温度 50、出清分 98 是固定赋值，并不是随当天数据计算。

离线调用 2026-10-08 和 2026-10-20，两次都输出同一个“试错确立/极致分化”阶段，并引用相同的10板、6板、换手34%等描述，虽然所代入的当天收盘价不同。这里的问题是时点和证据不匹配，不是本次判断这些市场描述一定为真或为假。

**建议：**

1. 旧版降为“历史案例库”；每条叙事注明适用区间、观点形成时间与事实来源。
2. 当前阶段只有一个计算入口，优先由证据引擎产生；未验证的旧版文字不能覆盖它。
3. 分离 `report_date`、`data_as_of`、`claim_as_of`、`known_at`，对未来形成的结论禁止历史回放展示。
4. 没有可计算依据的分数删除，或明确标成“主观复盘评分”；不能呈现成概率或模型置信度。
5. 测试不再要求页面必须出现“判死刑”等措辞，改测结论有效期、依据与失效条件。

### P0-2：缺价不能用固定值补成真实行情

旧版 398—402 行在缺价时给个股默认价格，又以固定基准 20.79 计算区间涨幅。用户看到的是数值，却看不到默认值来源及当日是否真实成交。

**建议：** 缺价返回 `null`，展示缺失原因；收益要求同一价格口径、明确基准日及完整数据。演示数值只能留在案例模式，并显式标为示例，不能进入实时判断。

### P0-3：过期参考数据遮蔽新行情

证据版 310—323 行只要补充参考行情在窗口内有行，就优先使用该序列，不比较它和全市场序列的最新可用日。

本地 2026-10-20 JSON 显示：全市场价格、涨跌停、广度均到 2026-10-20，参考个股源到 2026-10-08、落后8个交易日；医药、农业、消费篮子均显示“数据不足”。当前选择机制可以解释这种降级，不应据此认定篮子已经瓦解或仍然有效。

**建议：**

- 一个窗口选择一条口径一致、覆盖足够的完整序列；满足条件时优先使用更新的全市场前复权序列。
- 参考序列保留作交叉核验，不因为“曾经有数据”就永久拥有优先级。
- 禁止把不同来源或不同复权口径在窗口中静默拼接。
- 每成员显示实际数据日、价格口径、缺失交易日、源切换原因；总状态必须继承成员证据缺口。

### P0-4：已确认代理需要显式撤销与过期状态

证据版 `_scan`（229—247行）只更新新代理，没有主动撤销旧代理的分支。

离线合成样本复现：某股连续两天排名第一被确认，第三天已无任何合格候选，`stage` 为“等待”，但 `confirmed_proxy` 仍保留旧股。

**建议：** 区分 `last_confirmed_proxy` 和 `active_proxy`；增加 `active / at_risk / invalidated / stale / unknown`。明确价格失效规则、确认日期和最后验证日期。缺数据进入未知或过期状态，不能伪装成确认有效，也不能自动当作价格失效。

### P1-1：瓦解后的修复不能永久被状态记忆锁住

`assess_cohort` 的 `was_broken` 分支优先于“强化”，而历史循环只把 `was_broken` 从 False 更新为 True。

离线合成样本复现：全部成员已回到MA5上、5日收益为正且稳定5日，只要曾经瓦解，仍只能输出“出清观察”。

**建议：** 增加“修复待验证/修复有效”路径，保留过去的瓦解事件；不得仅凭两天反弹就自动抹除瓦解，也不得让一段历史记忆无限阻断后续修复。

### P1-2：历史时间轴没有覆盖当前报告的整个窗口

2026-10-20 JSON 的日扫描延伸到10月20日，但 `periods` 仍停在2026-10-08。原因是只有 `periods` 为空时才生成滚动观察窗口，固定参考分段存在就不会补充后面的日期。

**建议：** 历史案例分段与实时滚动分段分开呈现。实时层覆盖全部可用交易日；对尚未确认边界的区间使用“未定型观察”，不要为了图表完整强行创造一个真实周期。

## 三、最重要的框架补充：集中度和脆弱性分开

不要压成一个“抱团分”后用高分代表更值得买。建议输出两个独立研究维度：

1. **集中/持续程度**：相关群体的成交占比、相对收益、成员持续性、核心稳定性。
2. **脆弱程度**：成员减少、核心对少数个股依赖、下跌同步性、回撤、极端成交与可成交风险。

| 集中/持续程度 | 脆弱程度 | 建议研究解释 |
| --- | --- | --- |
| 上升 | 较低 | 可能为群体形成或健康强化，继续验证同伴扩散 |
| 上升 | 上升 | 可能为收缩或末端集中，不能把更集中等同于更安全 |
| 下降 | 上升 | 检查风险扩散、核心失效及候选失败 |
| 下降 | 下降 | 检查是否向更多方向扩散，而非直接认定退潮 |

这是解释矩阵，不是买卖信号。注意集中度分母：成员减少或全市场成交萎缩也可能让占比上升。必须同时展示占比、绝对成交、成员数和归因覆盖率。

### 分层输入，不重复计分

- **市场层**：广度的水平与变化、等权表现、涨跌停与昨日强势群体的后续表现。
- **群体层**：成员覆盖率、收益中位数、正超额收益占比、成交集中、昨日候选晋级与失败。
- **核心层**：价格持续性、距高点回撤、相对强度、波动、成交与历史流动性。
- **风险层**：旧核心失效是否扩散到同伴、候选失败是否增加、价格与成交是否背离。
- **执行层**：交易权限、证券状态、完整盘口/成交证据及模拟成交限制；该层是门禁，不是能被高分抵消的加分项。

5日收益、20日收益和价格排名高度相关，不宜机械堆叠后解释成多份独立证据。

## 四、将“换龙”“退潮”“切换”拆成三个问题

### 1. 同周期核心换位

验证的是同一冻结群体的内部变化：旧核心掉队时，同伴是否仍有持续性，新核心是否在当时已知的同群体里出现并跨日保持优势。

不能只靠全市场排名第一变化来证明同周期接替，更不能据此证明资金从A流向B。

### 2. 群体瓦解

固定当时核心篮子，观察多数成员价格失效、相对收益恶化以及亏损是否扩散。不得每天删除弱者、换入强者后再宣称“旧团健康”。

新关注池可以更新，但须创建新版本，并保留旧池作为对照。

### 3. 风格或主线切换

同时验证旧群体的变化、新群体的持续性、两者是否属于不同标签，以及市场层是否支持扩散。

**老团止跌可作为一种试错情景，不应成为所有新方向出现的必要前提。** 建议分别研究：旧团瓦解后重建、旧团仍在而新团并行、普涨环境中的风格切换。没有证据时允许两个假设共存。

## 五、状态机：允许分支、修复和未知

建议主路径：观察 → 形成待验证 → 强化 → 分歧 → 瓦解 → 止跌观察。

但应支持：

- 分歧 → 强化：价格与群体证据恢复。
- 分歧 → 收缩抱团：核心仍强，同伴与市场变弱。
- 止跌观察 → 旧团修复：仍是同一个旧篮子的恢复。
- 止跌观察 → 新团形成：新版本候选完成持续性验证。
- 任何阶段 → 数据未知：必要证据缺失；另存 `last_known_state`，不覆盖事实历史。

不要只看一天是否越过阈值。进入和退出规则应不同，记录观察期与确认滞后；例外风险事件单列。参数均需要校准，不能先指定“最佳天数”。

每个阶段输出四项：支持证据、反对证据、数据缺口、下一项验证条件。未做概率校准时只能写“证据充分度”，不能写“成功概率”。

## 六、候选池与代理排名的优化

当前评分由5日、20日横截面百分位和持续天数组成，强者分数容易挤在接近100的区间。此时榜首微小差距可能主要反映排序噪声，而不是可靠换位。

建议：

1. 核心集合替代唯一榜首；展示排名区间、分差、换位待验证状态，不把99.96与99.93理解成可交易优势。
2. 换位需要持续性与原代理失效/新代理优势证据，不仅是连续两天第一。
3. 起步试错池和趋势确认池分开：当前20日收益门槛属于已积累涨幅的持续性筛选，不能直接当作低位启动发现器。
4. 主板、创业板/科创板、北交所、ST、新股等按当日证券状态和制度分组；先研究组内排名，再研究跨组比较，避免当前标签污染历史。
5. 对流动性和证券状态未知的候选标记 `execution_unknown`，不得因为没有数据就假定可交易。
6. 价格缺失不等于停牌或跌停；缺失原因必须独立识别。
7. 全市场覆盖质量不仅看总行数，也检查分组覆盖和指标有效覆盖，以免大量缺失20日指标仍显示价格覆盖正常。

## 七、可成交性：强势与可参与是两个结果

建议状态明确分离：研究候选 / 价格持续性支持 / 群体支持 / 执行条件未知 / 可模拟参与。

没有执行模型时，停留在研究观察。下一阶段模拟需显式配置：信号形成时间、下一可成交时点、T+1约束、价格限制、停牌、跳空、费用、滑点、成交容量和未成交事件。

- 日线数据不能证明盘中买到或卖出；碰到涨停价不等于确定成交。
- 即使已有止损规则，也不能假设触发后立刻成交；保留无法卖出的损失路径。
- `close_qfq` 用于收益和技术研究；模拟委托需要当时原始价格及有效复权映射，不能直接拿复权价作为真实委托价。
- 没有高低开收、成交与盘口的历史覆盖时，先做有边界的事件研究，不伪装完整策略回测。

交易制度必须按对应日期、交易所和证券状态版本化。上交所已于2026-04-24发布《上海证券交易所交易规则（2026年修订）》，2026-07-06施行，并存在暂缓实施条文，实际执行须核对适用条款；不能用一个当前规则套全部历史。

## 八、验证：先验证状态和失效，再验证策略收益

### 事件记录建议

```text
observed_at / known_at / trade_date / source_as_of
candidate_set_id / candidate_version / member_codes
market_state / cohort_state / proxy_state / state_since
supporting_evidence / opposing_evidence / missing_evidence
invalidation_rule / rule_version
next_observation / simulated_fill_status
```

候选快照要保存原始时点，不把重跑结果覆盖成“当时版本”。同一日期补数后生成修订版本，保留原版与差异。

### 先回答的研究问题

- 形成待验证后，新群体是否持续强于同制度、相近规模与流动性的对照样本？
- 收缩抱团相对扩散型主线是否有不同的后续回撤和不可成交分布？
- 核心换位是真正降低风险，还是只增加频繁切换与成本？
- 止跌观察对新团形成有无增量解释力，还是已被广度和候选持续性解释？

记录未来固定观察窗内的收益、最大不利变动、失败率、确认滞后和样本数，保留失败、未成交、未结束及右删失事件；这些未来结果只用于标签和评估，不能反向进入信号。

### 防止研究选样和过拟合

- 按时间滚动训练/验证，而不是随机拆交易日；重叠事件设置隔离期，避免一个行情片段同时影响训练和测试。
- 参数选择只在训练区间完成，固定后进入样本外；报告全部尝试过的配置与敏感性，不只展示最好的阈值。
- 与简单5日动量、20日动量、单纯广度门禁做对照，检查抱团框架是否有增量价值。
- 失败样本、退市/证券状态变化、未成交不能删除；不同市场环境分开报告。

不要用“善水最终走出来，所以首板就应该识别”倒推策略正确。真正应验证的是：当时完整候选集合、已知信息、可成交机会，以及同规则筛出的失败标的。

## 九、验收顺序

### 第一批：P0，修口径而非加指标

- 实时结论与历史案例分离；未来观点不进入历史页面。
- 缺价返回未知；分数与事实都有形成日期。
- 单窗口数据源选择透明，解决参考旧源压住新源。
- 活跃代理拥有失效/过期状态。
- 新增机制测试，不以页面故事关键词作为正确性标准。

### 第二批：P1，完善生命周期

- 全窗口滚动时间轴与历史案例时间轴并存。
- 状态机支持修复、收缩及未知。
- 动态候选池和固定跟踪篮子分离并版本化。
- 复用现有集中度与晋级率，展示口径、分母和覆盖。
- 市场环境与群体状态二维判断，不要求所有新团等旧团出清。

### 第三批：P2，建立验证闭环

- 冻结真实候选快照和失效规则。
- 接入可靠且时点一致的量价证据。
- 做事件研究、执行仿真、样本外与参数敏感性检验。
- 在验证前不输出未经校准的胜率、固定仓位或自动交易确认。

### 分类身份与预声明条件

分类以当日原动态追踪规则的身份为共同参照，研究参数不倒写池身份：

1. 新生/新团：未入过池的候选及本轮新团。
2. 老团延续：已入池且跨过核心代理观察轮的延续。
3. 旧团修复/再验证：当日原追踪已入过池但退出，或处于修复状态的个股。
4. 边界存量：窗口首日已有收益候选；其真实出生在窗口前不能确定。首日放宽假设才覆盖的既有候选也不标作新生。

原动态追踪表保留原条件不变。研究分别模拟8组：原条件、1日先行、3日确认、候选前5%、候选前20%、回撤10%、5/20日收益放宽到2%/5%、收益收紧到6%/12%且持续性3日。均无固定个股名单，排名按当天完整候选截面计算，同分不按股票代码截断。阈值是预声明待检验假设，并不是自动发现的唯一最佳参数。

每个假设维护独立确认/退出状态，再按当日分类选取该池当天推荐假设下的资格。不同假设状态不能解释成一个可成交的自适应持仓组合。MA5相等附近使用1e-12数量级容差，避免浮点求和把横盘股错误判为跌破均线。

### 训练、标签与冻结检验

- 默认研究目标：入池收盘后5个交易日末收益≥5%，且期间各收盘相对入池收盘最低收益≥-10%。这只是一种价格标签，既不是日内最大回撤，也不是可成交盈亏。
- 条件搜索只使用 **标签成熟日严格早于观察日** 的事件。观察日当天刚成熟的标签也不进入本日选择；未满5日或期间缺价格/截面的事件保持未定，不当作失败。
- 每分类池至少20个成熟入池事件、6个不同入池日，才进行8组描述性比较。用Wilson保守下界排序，同分优先原条件；不足则原条件回退。不是为了找到赢家而临时调低样本要求。
- 另以前80%观察时段择优，最后20%时段冻结检验。冻结之前未成熟的标签不进入训练；验证阶段不重新选参数，同时列出原条件对照。两组事件数不同，不能当作配对显著性检验。
- 同一股票重复入池以及同日事件高度相关，Wilson下界仅作排序，不能视作独立样本置信保证。8组比较、短样本和市场状态漂移都有过拟合风险。
- 当前前复权缓存重建有复权修订和存活样本偏差，不是历史时点行情库。未纳入量能、开盘成交、封板排队、涨跌停限制、T+1、成本、组合风险；不能以“能被选中”推导“能买到”或“会盈利”。
