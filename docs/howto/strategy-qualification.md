# 逐策略资格：退出“永久观察”的正确方式

本改动把整体数据健康与单个策略许可分开。它修复“条件永远接不上”的工程问题，**不宣称现有策略已经完成独立验证，也不会自动批准策略**。

## 状态怎样变化

| 实际情况 | 报表结论 |
|---|---|
| 核心行情缺失、过期、错日或混批次 | 全部策略阻断，不开新仓 |
| 只有AI文案失败 | 确定性文案继续；已独立验证的规则策略不受此项阻断 |
| 一个策略的必要数据缺失 | 只阻断该策略，并列出缺少的模块或事件字段 |
| 没有独立验证报告，或策略/规则/口径不匹配 | 未验证，只研究观察 |
| 策略与数据合格，只有收盘快照 | 条件预案，等待目标交易日确认；不是不可评估，也不标已触发 |
| 目标交易日合格阶段快照满足规则 | 进入该策略条件计划；不是订单或成交 |
| 已验证但本次无适用事件 / 无候选 | 不适用 / 无候选，不再伪装成数据不足 |

## 统计输入不再混用

择时模块的 `win_rate_sample_size` 映射到 `descriptive_statistics.sample_size`，只表示历史同型统计。策略授权使用独立的 `strategy-validation/v1` 记录；市场场景的 T+1/T+3 命中率、历史行情天数和简单计数不自动转成策略验证。

正式日报默认只读 `data/strategy_validation.json`；未提供就保持未验证。该本地文件已被 Git 忽略，不能把实际研究/成交样本顺手提交。公开审计、预测和重放上下文只含资格摘要，不含原始验证样本。

### 只读检查

```powershell
python tools/check_strategy_qualification.py --audit output/audit/2026-09-04.json --validation-file data/strategy_validation.json
```

输出当前策略ID、期望的规则指纹、所需数据、验证文件状态与具体阻断项。命令不会建立批准记录、修改报表或伪造回测。

### 验证记录格式

顶层必须是 `{"schema_version":"strategy-validation-set/v1","records":[...]}`。每份记录来自已经独立评估的策略研究，包含：

- `strategy_id`：现有场景ID；未知策略拒绝。
- `rule_version`：`scenario-rules/v1`。
- `rule_fingerprint`：检查命令给出的当前规则指纹，包含触发、失效、仓位、执行版本和依赖。阈值变化需要新的验证，不能沿用旧批准。
- `outcome_definition_id`：`trade-plan-net-return/v1`，不是 `market-thesis/v1`。
- `method`：`out_of_sample`，`status`：独立评估的结论；只有显式 `passed` 才可能通过。
- `source` 与 `evidence_ref`：真实验证来源和可追溯报告引用，不得填unknown。
- `trained_through`、带时区的 `evaluated_at`、`valid_from`、`valid_until`：防止训练样本、未来结果及过期授权混用。
- `sample_size` 与 `samples`：数量必须一致且不少于原门槛10个唯一有效样本；此下限不是“10笔足以证明赚钱”。
- 每个样本具备 `sample_id`、相同的策略ID/规则指纹/结果定义、`trade_date`、`outcome_date`、有限的 `net_return`、`costs_included:true`、真实 `source`。缺失、未成熟、重复或混版本样本不授权。
- 结果只有 `outcome_date` 时，必须严格早于 `evaluated_at` 对应的上海日期；同日结果不能仅凭日期视为已成熟。同日样本需要提供带时区的 `outcome_matured_at`，其上海日期须与 `outcome_date` 一致、时刻不晚于评估时刻。不要补造收盘或结算时间。

程序校验的是外部验证记录的契约与一致性，**不会仅凭收益为正或样本数达标自动认定策略优秀**。是否应将研究结论标为passed，必须由实际的独立评估决定。仓位阈值、胜率门槛没有为生成买入名单而降低。

## 事件字段与样本范围

- 炸板率、回封率、板型分别输出 `ready / missing / invalid / not_applicable`。
- 完整观测且没有炸板时，回封率为 `not_applicable`、值仍为null；不是缺失，也不是0%回封成功率。
- 存在炸板而回封记录缺失时仍为missing。非法分母、比率和计数矛盾为invalid；观测数与交集必须能同时成立，不能以指标自己的分母证明覆盖完整。
- 完整观测明确为零尝试、零炸板时，回封仍不适用；此时炸板率本身无分母，不填成0%。只缺未炸板股票的回封标记，不应阻断已完整观察的炸板股票回封结果。
- 明确未尝试封板的行不进入“尝试封板”分母。
- 字段齐全不等于全市场范围齐全。依赖市场炸板/回封率的策略要求完整封板尝试总体的同日来源证据；收盘涨停池不能冒充。
- 核心抱团策略检查当前候选的板型，不因无关股票板型缺失被捆绑阻断；也不能借其他股票的覆盖率授权自己。
- 主线延续可以接受完整观测但无历史炸板的回封率不适用；分歧回封策略没有适用事件时保持不启用。观察/防守分支不会因改名而成为交易策略。

## 必需数据的日期与批次契约

- 核心与本策略结构模块须带有明确的报告适用日（`lineage.report_date`或显式data_as_of）和同一run_id；缺失、矛盾或任一层显式stale/expired都不能授权。
- 采集时间与数据适用日分开：证券主表可以早于报告日更新，但须明确当前报告使用的证券范围；不能把旧采集时间改成当天冒充新数据。
- 主报告生产者显式传递适用日；昨日逐股差异保留当前快照report_date/run_id及previous_report_date，防止计算结果丢掉血缘。
- 聚合批次差异若只来自非必需、非critical的AI等模块，仅作非阻断诊断；核心或本策略依赖的批次不一致仍阻断。
- 旧审计即使写了status=ok，也不等于已经具备上述元数据；重放会指出缺少的日期/批次字段并降为仅事实展示，不倒填通过。应使用新版本从有效来源重建审计，再核验独立策略证据。
- 被拒绝的验证记录及旧资格摘要只能公开白名单标量元数据，不能通过source/evidence_ref/日期等字段夹带原始samples。

## 盘中确认与撤销

`record_market_phase.py` 增加 `--validation-file`；默认重新读取上述本地文件。验证撤销/过期、规则变化、必要数据变化会取消许可。原预案没有获准的策略，不因后来换一份验证文件就自动升级，需重建预案。 旧版日志没有原始逐策略授权时只保留分析，不凭历史样本数补授权；原报告的observation/facts_only上限、报告日/目标日和规则/结果口径绑定都会保留。回放持久化保存本次实际有效或已撤销的资格，不能拿旧的可用摘要覆盖撤销结果。

保持原有报告日/目标交易日、上海时段、来源质量、预测ID绑定与硬失效规则。盘后没有盘中快照很正常；只要资格已通过就显示“等待确认”。仍不自动抓取阶段行情、不新增定时任务、不下单。

## 离线比较

```powershell
python tools/preview_recap_report.py --audit output/audit/2026-09-04.json --validation-file data/strategy_validation.json --output-dir output/strategy_qualification_validation/preview
```

只在预览目录写HTML、CSV和模拟日志，不改正式行情、历史决策或验证文件。 默认预览遇到没有逐策略资格的旧审计时，也会明确标记未验证，不将旧decision徽标或历史样本数当作授权；不会隐式读取并批准新的验证资料。没有真实验证资料的历史报告仍会观察，页面会说明具体原因；测试中的合格记录仅是夹具，不会复制到生产文件。
